# REVIEW.md

Defects found in the starter `app/main.py`, and how each was fixed.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Builds shift start with `punch_in.replace(hour=...)`, i.e. on the punch-in's own (UTC or server-local) calendar day, not in IST. | Punch in at 09:40 IST on a server in UTC: the "shift start" lands on the wrong clock time and the result is wrong by 5h30m. | Shift start is built as an IST datetime on the record's attendance date; all subtraction happens between aware datetimes. |
| 2 | `compute_late_minutes` | Grace check is `minutes > 10` after truncating to whole minutes, so 09:40:30 (10m30s late) gives 0 instead of 10. Also uses `int(float/60)`. | Punch in at 09:40:01 and expect `late_minutes = 10`. | Work in integer seconds: late only if `seconds > 600`, then `seconds // 60` counted from shift start (R2). |
| 3 | `compute_late_minutes` / `punch_in` | No overnight-shift handling: a 22:00-06:00 employee punching in at 02:00 is compared against 22:00 *today*. | Overnight employee punching in after midnight gets a negative or zero lateness and the wrong `date`. | `attendance_date()` assigns early-morning punch-ins to the previous day for overnight shifts (R1); `shift_end_dt()` adds a day when `shift_end <= shift_start`. |
| 4 | `compute_work_hours` | Python `round()` is banker's rounding on a float, so exact halves round to even (0.005 h -> 0.0) and float error creeps in. | 18 seconds of work should be 0.01 h under half-up. | Integer maths: `half_up_div(seconds * 100, 3600) / 100` (R4). |
| 5 | `compute_overtime` | Returns every minute after shift end; ignores the 30-minute minimum. Uses `fromisoformat(date).replace(...)` and never adds a day for overnight shifts. Compares aware vs possibly naive values. | Punch out 10 minutes after shift end returns 10 instead of 0. | Whole minutes via integer seconds, counted only when >= 30 (R3); overnight end handled; everything timezone-aware. |
| 6 | `punch_in` | `datetime.fromtimestamp(ms / 1000)` uses the server's local timezone and produces a naive datetime; float division loses precision. | Behaviour changes with the server's TZ; stored instants are not UTC. | `EPOCH + timedelta(milliseconds=ms)` (exact, UTC, aware), truncated to whole seconds (R1). |
| 7 | `punch_in` | `if body.punched_at` treats `0` as "missing"; any value (floats, seconds instead of ms, negatives) is accepted. | Send `punched_at: 1783312500` (seconds) and a 1970 record is created. | `EpochMs` is a strict int with a sane range; anything else is a 422. `None` is tested with `is not None`. |
| 8 | `punch_in` | Employee lookup result is never checked: unknown `emp_code` raises `TypeError` on `emp["shift_start"]` -> 500. | `POST /attendance/punch-in` with an unknown code. | Explicit 404. |
| 9 | `punch_in` | `date` comes from `ts.date()` in server-local time, not IST, and ignores overnight shifts (R1). | Punch in at 00:30 IST on a UTC server: record lands on the wrong day. | `attendance_date()` converts to IST first. |
| 10 | `punch_in` | Check-then-insert race: two simultaneous requests both pass `find_one` and both insert. No unique index exists. | Fire two identical requests in parallel: two 201s, duplicate records. | Unique index on `(emp_code, date)` created at startup; insert and catch `DuplicateKeyError` -> 409. |
| 11 | `punch_in` | `status` is any string (e.g. `"ABSENT"` or `"banana"`), and the response leaks an extra `id` field and returns raw datetimes instead of epoch milliseconds. | `status: "banana"` is accepted; response timestamps are not integers. | `status` is a `Literal` of the three presence values; responses go through `record_out()` (epoch ms, contract fields only). |
| 12 | `create_employee` | Same check-then-insert race (no unique index on `emp_code`); `created_at = datetime.now()` is naive local time; the returned document has a raw datetime and is not validated: no emp_code pattern, email shape, real `joined_on` date, `HH:MM` shifts, or `shift_start != shift_end`. | Duplicate parallel creates; `joined_on: "2026-02-30"` accepted; `created_at` not epoch ms. | Unique index + `DuplicateKeyError` -> 409; Pydantic patterns and validators -> 422; UTC `created_at` returned as epoch ms. |
| 13 | `list_employees` | `skip = page * page_size` skips the whole first page (pages are 1-based); `total` counts the whole collection, ignoring the `department` filter; no sort so pages are unstable; no bounds on `page` / `page_size`. | Page 1 returns what should be page 2; `total` is wrong with `?department=`. | `skip = (page - 1) * page_size`, `count_documents(query)`, `sort emp_code`, `page >= 1`, `1 <= page_size <= 100` (R10). |
| 14 | `list_attendance` | Loads every matching document into Python memory, sorts and slices there. No tie-breaker in the sort, no `emp_code` secondary order. Leaks `id`, raw datetimes. | 100k records: slow and memory-hungry; same-date rows come back in arbitrary order. | Database-side `sort(date desc, emp_code asc)`, `skip`/`limit`, supporting indexes, `record_out()` serializer. |
| 15 | `list_attendance` | No validation of `date_from`, `date_to`, `status`, `page`, `page_size`; `date_from > date_to` silently returns nothing. | `?date_from=garbage`, `?page=0`, `?status=XYZ` are accepted. | Real-date validation, enum for `status`, `date_from <= date_to`, bounded paging -> 422. |
| 16 | `health` | Always returns ok, even when MongoDB is unreachable. | Stop MongoDB and call `/health`. | Pings the database; 503 if it cannot be reached. |
| 17 | Startup / client | `MongoClient` without `tz_aware=True` returns naive datetimes, which breaks comparisons with aware datetimes. No indexes are created anywhere; no server selection timeout. | `TypeError: can't subtract offset-naive and offset-aware datetimes`; collection scans. | `tz_aware=True, tzinfo=UTC`, `serverSelectionTimeoutMS=5000`, idempotent `ensure_indexes()` at startup with background retry. |

## Looked at and decided NOT a defect

- **`load_dotenv()` with default `override=False`.** Real environment variables already win over `.env`, which is what we want.
- **`{"_id": 0}` projection in `list_employees`.** Fine for hiding `_id`; I replaced it with an explicit serializer only for consistency.
- **Plain `def` (synchronous) endpoints with PyMongo.** FastAPI runs them in a thread pool, so they do not block the event loop. Using `async def` with a blocking driver would be the real mistake.
- **Storing `date` as an `"YYYY-MM-DD"` string.** It sorts and range-queries correctly as text and is what the data model specifies.
- **Default shifts `09:30` / `18:30`.** These match the data model.
- **`punch_out` left unchanged by punch-in.** Correct: it is `null` until punch-out.
